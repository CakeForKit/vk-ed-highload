#### Формулы:
Условная доля в хранилище = ((Процент от количества видео шт.) * (Вес 1 минуты)) / СУММА((Процент от количества видео шт.) * (Вес 1 минуты)) * 100%

Средний вес 1 минуты = 0.05 * 50 + 0.45 * 15 + 0.30 * 11 + 0.20 * 7 = 13,95 МБ.

Средний вес 1 видео = 13,95 МБ * ~14,8 минут = 206,46 МБ.

Объём N видео = N * 206,46 МБ.

#### Допущения для рекомендаций:
- Для пользователя хранится один актуальный список из 500 рекомендаций.
- Один элемент списка занимает 32 Б: идентификатор видео, оценка и время обновления.
- Список занимает 500 * 32 Б = ~16 КБ на пользователя.
- Списки активных пользователей (DAU) обновляются один раз в сутки; предыдущий список заменяется новым.

### RPS по типам запросов

```
Средний RPS = (Количество действий пользователя за сутки) / 86 400 секунд в сутках
Пиковый RPS = Средний RPS * Коэффициент пиковости (3)
Расчётный RPS с запасом = Пиковый RPS * Коэффициент запаса (1,3)
```

### CDN

Видео составляет около 96% трафика, поэтому CDN размещается плотнее ЦОД: 18 узлов.
- В России (13 узов): Москва, Санкт-Петербург, Нижний Новгород, Ростов-на-Дону, Краснодар, Махачкала, Казань, Самара, Екатеринбург, Новосибирск, Красноярск, Иркутск, Хабаровск и Владивосток.
- За пределами России: 
  - Минск, Алматы и Ташкент (каждый из трёх зарубежных рынков получает одинаковое число CDN-узлов — 1 шт).
  - Армения, Азербайджана и Грузии: общий кавказский узел в Тбилиси.


###  Схема балансировки
1. Определяем регион с помощью Geo-Based DNS
    - Выбирает какой набор IP-адресов региона вернуть клиенту.
    - На основе IP dns резолвера клиента (8.8.8.8, 1.1.1.1 и т д) выбирается пул адресов закрепленный за регионом
2. В рамках региона выбираем датацентр через BGP Anycast
    - Анонсируются маршруты до датацентра
    - Выбирается самый быстрый маршрут

# 4. Локальная балансировка нагрузки

96% трафика - видеопоток - идет через CND:
- CDN отдаёт видео с ближайшего Edge-сервера => минимальная задержка.
- Кеширование снижает нагрузку на исходное видео.

Все остальное по схеме:
```
Direct Routing (L3/L4, внутри ЦОД) → L7 (HTTP/gRPC)
```

### Транспортная балансировка (L3/L4)
Используем Direct Routing внутри ЦОД. Балансировщик выбирает доступный сервер и меняет MAC-адрес назначения; ответ клиенту сервер отправляет напрямую, минуя балансировщик.

Резервирование с помощью протокова VRRP -  активный и резервный узел, VIP (виртуальный ip дарес) переходит за < 1 с при отказе.

Формула резервирования: N+1

### L7 (HTTP/gRPC)

Для коротких API-запросом (например получить данные о пользователе, загрузить мету видео, до его показа)

Будем использовать NGINX, так как:
- SSL Termination — обязательна для HTTPS. Nginx расшшифровывает трафик и передает дальше
- Маршрутизация по путям — /api/v1/video, /api/v1/comments, /api/v1/upload.
- Keep-alive / TCP multiplexing — NGINX держит пул уже открытых соединений с микросервисами и переиспользует их.
- Автоматическое переключение при сбое

Формула резервирования: N*1
